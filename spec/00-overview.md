# NodeRAG: Обзор Системы

## Введение

NodeRAG - это гетерогенная граф-ориентированная система RAG (Retrieval-Augmented Generation), которая структурирует знания из документов в виде многоуровневого графа с различными типами узлов. Система использует языковые модели для извлечения семантической информации и построения концептуального слоя знаний.

## Основная Архитектура

NodeRAG состоит из последовательности pipeline'ов, которые обрабатывают документы на разных уровнях абстракции:

```
Документы (raw text)
    ↓
Text Units (семантические chunks)
    ↓
Semantic Units + Entities + Relationships
    ↓
Attributes (для важных узлов)
    ↓
High-Level Elements (концептуальный слой)
    ↓
Граф Знаний + Векторные Индексы
```

## Типы Узлов Графа

NodeRAG использует гетерогенный граф с различными типами узлов:

### 1. **Document Nodes**
- Представляют исходные документы
- Хранят метаинформацию о файлах

### 2. **Text Unit Nodes**
- Chunks текста, полученные семантическим разбиением
- Базовая единица для дальнейшей обработки

### 3. **Semantic Unit Nodes**
- Семантически связные единицы информации
- Результат декомпозиции Text Units через LLM
- Содержат суммаризированную информацию о конкретных событиях/фактах

### 4. **Entity Nodes**
- Извлеченные сущности (люди, организации, места, концепты)
- Нормализованы в UPPERCASE формате
- Могут иметь частотные веса

### 5. **Relationship Nodes**
- Представляют связи между сущностями
- Формат: (source_entity, relation_type, target_entity)
- Хранят контекстную информацию о связях

### 6. **Attribute Nodes**
- Детальные описания важных сущностей
- Генерируются только для высокочастотных узлов
- Содержат агрегированную информацию из соседних узлов

### 7. **High-Level Element Nodes**
- Концептуальный слой системы
- Темы, идеи, теории, выявленные через community detection
- Связывают семантически близкие кластеры

## Ключевые Концепции

### Гетерогенность
Граф содержит узлы разных типов, каждый со своими свойствами и ролью в системе.

### Многоуровневость
Система создает иерархию от сырых текстов до высокоуровневых концепций.

### Семантическая Связность
Разбиение и обработка учитывают семантические границы, а не только формальные критерии.

### Инкрементальность
Система поддерживает добавление новых документов без полной переиндексации.

## Роль Языковых Моделей

LLM в NodeRAG выполняют следующие функции:

1. **Semantic Decomposition** - разбиение текста на семантические единицы
2. **Entity Extraction** - извлечение сущностей
3. **Relationship Extraction** - выявление связей
4. **Attribute Generation** - создание описаний важных сущностей
5. **Community Summarization** - генерация концептов высокого уровня
6. **Embedding Generation** - создание векторных представлений

## Структура Pipeline

1. **INIT Pipeline** - проверка файлов и инкрементальности
2. **Document Pipeline** - загрузка и первичное разбиение документов
3. **Text Pipeline** - семантическая декомпозиция через LLM
4. **Graph Pipeline** - построение графа из извлеченной информации
5. **Attribute Pipeline** - генерация атрибутов для важных узлов
6. **Embedding Pipeline** - создание векторных представлений
7. **Summary Pipeline** - community detection и генерация концептуального слоя
8. **Insert Text Pipeline** - вставка текстовых узлов в граф
9. **HNSW Pipeline** - построение HNSW индексов для быстрого поиска

Каждый pipeline работает асинхронно, обрабатывая данные параллельно где это возможно.

## Хранение Данных

Система использует комбинацию форматов:

- **Parquet** - для структурированных данных узлов
- **Pickle** - для серилизации графа NetworkX
- **JSONL** - для промежуточных результатов LLM
- **Faiss/HNSW** - для векторных индексов
