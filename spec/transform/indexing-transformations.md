# Семантические преобразования при индексации

## Обзор

Этот документ описывает семантические преобразования, выполняемые агентами NodeRAG при индексации документов. Каждое преобразование трансформирует данные из одного семантического представления в другое, обогащая структуру знаний.

---

## Сравнительная таблица преобразований при индексации

| № | Тип преобразования | Агент/Компонент | Вход | Выход | Критичность | Стадия |
|---|-------------------|-----------------|------|-------|-------------|--------|
| 1 | Семантическое разбиение | SemanticTextSplitter | Документ (любой размер) | Text Units (~1048 токенов) | Средняя | Stage 1 |
| 2 | Декомпозиция текста | Text Decomposition Agent (LLM) | Text Unit | Semantic Units + Entities + Relationships | **КРИТИЧЕСКАЯ** | Stage 2 |
| 3 | Реконструкция отношений | Relationship Reconstruction Agent (LLM) | Некорректная связь | Исправленная тройка {source, relation, target} | Низкая | Stage 3 |
| 4 | Генерация атрибутов | Attribute Generation Agent (LLM) | Entity + контекст | Нарративное описание (100-2000 слов) | **КРИТИЧЕСКАЯ** | Stage 4 |
| 5 | Обобщение сообществ | Community Summary Agent (LLM) | Community cluster | High-Level Elements (темы + описания) | **КРИТИЧЕСКАЯ** | Stage 6 |
| 6 | Генерация эмбеддингов | Embedding Models (OpenAI/Gemini) | Текст | Векторное представление (512-1536 dim) | Высокая | Stage 5, 6 |
| 7 | Построение графа | Graph Pipeline | Декомпозиция | Гетерогенный NetworkX граф | Высокая | Stage 3 |
| 8 | Обнаружение сообществ | Leiden Algorithm | Граф знаний | Кластеры узлов | Средняя | Stage 6 |

## Детальные характеристики преобразований

### 1. Семантическое разбиение (Semantic Chunking)

#### Семантические характеристики
- **Сохранение границ**: Уважает семантические границы (абзацы, предложения)
- **Приоритет разделителей**: `\n\n` > `\n` > `.` > `!` > `?` > `;`
- **Целостность контекста**: Сохраняет нарративный поток
- **Размер**: ~1048 токенов на единицу

#### Связь с цепочкой преобразований
- **Вход цепочки**: Первое преобразование в pipeline
- **Следующий этап**: Text Units → Text Decomposition
- **Зависимости**: Нет (начальное преобразование)

#### Роль в индексации
- Подготавливает данные для LLM-обработки
- Обеспечивает оптимальный размер контекста
- Минимизирует потерю семантической связности

#### Пример
```
Вход: Документ 3000 токенов

Выход: 3 Text Units
  - Unit 1: 950 токенов (разбит на границе абзаца)
  - Unit 2: 1020 токенов (разбит на границе абзаца)
  - Unit 3: 1030 токенов (остаток документа)
```

---

### 2. Декомпозиция текста (Text Decomposition) ⭐

#### Семантические характеристики
- **Атомарность**: Выделение единичных фактов/событий
- **Перефразирование**: Сжатие с сохранением ключевых деталей
- **Экстракция сущностей**: Идентификация всех именованных сущностей
- **Нормализация**: UPPERCASE для сущностей, формат дат (2024-09)
- **Связность**: Извлечение отношений как {source, relation, target}

#### Связь с цепочкой преобразований
- **Предыдущий этап**: Text Units → Decomposition
- **Следующий этап**: Decomposition → Graph Construction
- **Зависимости**: Требует семантически целостных Text Units

#### Роль в индексации
- **Центральное преобразование**: Основа всей структуры знаний
- Преобразует неструктурированный текст в структурированные элементы
- Создает фундамент для графа знаний
- Обеспечивает точность извлечения фактов (Temperature 0.0)

#### Пример
```json
Вход: "В сентябре 2024 года доктор Эмили Робертс посетила Париж для участия
       в Международной конференции по возобновляемой энергии."

Выход:
{
  "semantic_unit": "В сентябре 2024 года доктор Эмили Робертс приняла участие
                    в Международной конференции по возобновляемой энергии в Париже.",
  "entities": [
    "DR. EMILY ROBERTS",
    "2024-09",
    "PARIS",
    "INTERNATIONAL CONFERENCE ON RENEWABLE ENERGY"
  ],
  "relationships": [
    "DR. EMILY ROBERTS, attended, INTERNATIONAL CONFERENCE ON RENEWABLE ENERGY",
    "INTERNATIONAL CONFERENCE ON RENEWABLE ENERGY, located in, PARIS"
  ]
}
```

#### Подтипы семантических трансформаций
1. **Сегментация**: Текст → атомарные семантические единицы
2. **Парафраз**: Оригинал → краткая форма с деталями
3. **Извлечение сущностей**: Текст → нормализованные ENTITIES
4. **Извлечение отношений**: Текст → triplets
5. **Темпоральная нормализация**: "сентябрь 2024" → "2024-09"

---

### 3. Реконструкция отношений (Relationship Reconstruction)

#### Семантические характеристики
- **Исправление формата**: Некорректные связи → корректные тройки
- **Разбор**: Декомпозиция неправильной строки
- **Уточнение**: Прояснение типа отношения

#### Связь с цепочкой преобразований
- **Триггер**: По требованию при обнаружении ошибки формата
- **Частота**: ~5% отношений
- **Контекст**: Stage 3 (Graph Pipeline)

#### Роль в индексации
- Восстановление качества данных
- Обеспечение консистентности графа
- Минимизация потери информации

#### Пример
```
Вход: ["DR. EMILY ROBERTS", "attended conference in Paris"]

Выход:
{
  "source": "DR. EMILY ROBERTS",
  "relationship": "attended conference in",
  "target": "PARIS"
}
```

---

### 4. Генерация атрибутов (Attribute Generation) ⭐

#### Семантические характеристики
- **Агрегация контекста**: Сбор всех упоминаний из соседей графа
- **Синтез**: Объединение множественных фактов в связное повествование
- **Приоритизация**: Выбор важнейшего контекста при лимите токенов
- **Стилевая трансформация**: Факты → "характеристика персонажа" или "описание продукта"
- **Дедупликация**: Удаление избыточной информации

#### Связь с цепочкой преобразований
- **Предыдущий этап**: Graph Construction → Attribute Generation
- **Входы**: Entity + Related Semantic Units + Related Relationships
- **Выход**: Атрибутивный узел в графе
- **Следующий этап**: Embedding Generation

#### Роль в индексации
- **Обогащение сущностей**: Добавляет контекстуальную глубину
- Улучшает качество поиска через описательные атрибуты
- Создает нарративный контекст для важных сущностей
- Применяется селективно (10-15% сущностей)

#### Критерии отбора
- K-core decomposition
- Betweenness centrality
- Weight > 1

#### Пример
```
Вход:
  Entity: DR. EMILY ROBERTS
  Semantic Units:
    - "Доктор Эмили Робертс посетила конференцию в Париже"
    - "Доктор Эмили Робертс опубликовала исследование о солнечных панелях"
    - "Доктор Эмили Робертс возглавляет команду в Европейском исследовательском институте"
  Relationships:
    - "DR. EMILY ROBERTS, works at, EUROPEAN RESEARCH INSTITUTE"
    - "DR. EMILY ROBERTS, researches, SOLAR PANEL EFFICIENCY"

Выход (Attribute):
"Доктор Эмили Робертс - видный исследователь в области возобновляемой энергии,
специализирующийся на повышении эффективности солнечных панелей. В сентябре 2024
года она сыграла ключевую роль на Международной конференции по возобновляемой энергии
в Париже, где представила революционное исследование. Как ведущий ученый Европейского
исследовательского института, доктор Робертс установила многочисленные партнерства
с европейскими компаниями для продвижения технологий устойчивой энергетики..."
```

### 5. Обобщение сообществ (Community Summarization) ⭐

#### Семантические характеристики
- **Абстракция**: Конкретные факты → высокоуровневые темы/концепции
- **Тематическая экстракция**: Выявление концепций, теорий, воздействий, ключевых идей
- **Разнообразие**: Выбор неизбыточных элементов
- **Сжатие размерности**: Много фактов → несколько концепций
- **Генерация заголовков**: Краткие описательные названия (2-5 слов)
- **Синтез описаний**: Всеобъемлющие описания (100-200 слов)

#### Связь с цепочкой преобразований
- **Предыдущий этап**: Community Detection (Leiden) → Summarization
- **Входы**: Кластеризованные данные (Semantic Units + Attributes)
- **Выход**: High-Level Elements
- **Следующий этап**: Embedding Generation → HNSW Indexing

#### Роль в индексации
- **Высокоуровневое понимание**: Создает концептуальный слой
- Обеспечивает тематический поиск
- Поддерживает multi-hop reasoning
- Обнаруживает скрытые паттерны и связи

#### Пример
```
Вход (тексты сообщества):
  - "Доктор Эмили Робертс посетила конференцию по возобновляемой энергии в Париже"
  - "Исследование эффективности солнечных панелей"
  - "Джон Миллер провел исследование в Амазонии о вырубке лесов"
  - "Оба вносят вклад в сохранение окружающей среды"

Выход:
{
  "high_level_elements": [
    {
      "title": "Исследования и инновации в возобновляемой энергии",
      "description": "Передовые исследования в области технологий устойчивой
                      энергетики, фокусирующиеся на повышении эффективности
                      солнечных панелей и международном сотрудничестве через
                      научные конференции."
    },
    {
      "title": "Сохранение биоразнообразия и экосистемные исследования",
      "description": "Полевые исследования, документирующие разнообразие видов и
                      анализирующие воздействие вырубки лесов на критические
                      экосистемы."
    },
    {
      "title": "Охрана окружающей среды через науку",
      "description": "Пересечение различных научных дисциплин, работающих над
                      защитой окружающей среды, объединяющее технологические
                      инновации с экологическим сохранением."
    }
  ]
}
```

### 6. Генерация эмбеддингов (Embedding Generation)

#### Семантические характеристики
- **Семантическое кодирование**: Текст → плотное векторное пространство
- **Сохранение сходства**: Семантически близкие тексты → близкие векторы
- **Батчевая обработка**: Эффективная параллельная трансформация
- **Нормализация**: Консистентные векторные представления

#### Связь с цепочкой преобразований
- **Применяется к**: Text Units, Semantic Units, Attributes, High-Level Elements
- **Стадии**: Stage 5 (основные узлы), Stage 6 (сообщества)
- **Следующий этап**: HNSW Indexing

#### Роль в индексации
- Обеспечивает семантический поиск
- Поддерживает векторное сходство
- Основа для гибридного поиска (векторный + граф)

#### Модели
- **OpenAI**: text-embedding-3-small, text-embedding-ada-002 (512-1536 dim)
- **Gemini**: text-embedding-004 (768 dim)

#### Параметры
- Batch Size: 100 (по умолчанию)
- Normalize: True

---

### 7. Построение графа (Graph Structure Transformation)

#### Семантические характеристики
- **Типизация узлов**: Создание гетерогенных узлов с свойствами
- **Формирование рёбер**: Связи Semantic Unit → Entity, Relationship → Entity
- **Агрегация весов**: Инкремент весов для дубликатов
- **Дедупликация на основе хэша**: Объединение идентичного контента (hash_id)
- **Структурирование отношений**: Цепочки Source → Relationship → Target

#### Связь с цепочкой преобразований
- **Предыдущий этап**: Text Decomposition → Graph Construction
- **Следующий этап**: Attribute Generation, Community Detection
- **Параллельные процессы**: Embedding Generation

#### Роль в индексации
- **Структурирование знаний**: Превращает плоские данные в граф
- Обеспечивает навигацию по связям
- Поддерживает graph-based reasoning
- Основа для Personalized PageRank

#### Типы узлов
- `semantic_unit`: Атомарные факты
- `entity`: Сущности
- `relationship`: Связи между сущностями
- `attribute`: Описания сущностей
- `text_unit`: Исходные фрагменты текста
- `high_level_element`: Тематические концепции

---

### 8. Обнаружение сообществ (Community Detection)

#### Семантические характеристики
- **Кластеризация**: Группировка семантически связанных узлов
- **Оптимизация модульности**: Максимизация внутригрупповых связей
- **Иерархическая организация**: Неявная семантическая иерархия

#### Связь с цепочкой преобразований
- **Предыдущий этап**: Graph Construction → Community Detection
- **Следующий этап**: Community Summarization
- **Алгоритм**: Leiden

#### Роль в индексации
- Обнаружение тематических кластеров
- Подготовка к высокоуровневому обобщению
- Поддержка multi-level reasoning

## Цепочка преобразований при индексации

```
📄 Raw Document
     ↓
[1] Semantic Chunking (SemanticTextSplitter)
     ↓
📝 Text Units (~1048 tokens)
     ↓
[2] Text Decomposition ⭐ (LLM Agent, Temperature 0.0)
     ↓
{semantic_units, entities, relationships}
     ↓
[7] Graph Construction
     ↓
🕸️ Knowledge Graph (NetworkX)
     ├─→ [4] Attribute Generation ⭐ (LLM, 10-15% entities)
     │        ↓
     │   📋 Attributes
     │        ↓
     └─→ [6] Embedding Generation (Text Units, Semantic Units, Entities)
              ↓
         🔢 Embeddings (512-1536 dim)
              ↓
         [8] Community Detection (Leiden)
              ↓
         👥 Communities
              ↓
         [5] Community Summarization ⭐ (LLM Agent)
              ↓
         🎯 High-Level Elements
              ↓
         [6] Embedding Generation (High-Level Elements)
              ↓
         📊 HNSW Index
```

| Преобразование | Temperature | Детерминизм | Частота | Latency |
|---------------|-------------|-------------|---------|---------|
| Semantic Chunking | N/A | Детерминированное | 100% документов | Низкая |
| Text Decomposition | 0.0 | Детерминированное | 100% Text Units | Средняя |
| Relationship Reconstruction | 0.0 | Детерминированное | ~5% отношений | Низкая |
| Attribute Generation | 0.0 | Детерминированное | 10-15% сущностей | Высокая |
| Community Summarization | 0.0 | Детерминированное | Каждое сообщество | Средняя |

## Семантическая иерархия

```
Уровень абстракции (высокий → низкий):

High-Level Elements (темы, концепции)
          ↓
    Attributes (описания сущностей)
          ↓
      Entities (нормализованные сущности)
          ↓
    Relationships (связи между сущностями)
          ↓
  Semantic Units (атомарные факты)
          ↓
    Text Units (исходные фрагменты)
          ↓
  Raw Document (оригинальный текст)
```

Каждый уровень представляет собой семантическую трансформацию, увеличивающую абстракцию и структурированность данных.
