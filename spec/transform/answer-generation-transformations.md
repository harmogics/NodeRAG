# Семантические преобразования при генерации ответа

## Обзор

Этот документ описывает семантические преобразования, выполняемые агентами NodeRAG при генерации ответов на запросы пользователей. Эти преобразования используют проиндексированную структуру знаний для создания точных и контекстуальных ответов.

---

## Сравнительная таблица преобразований при генерации ответа

| № | Тип преобразования | Агент/Компонент | Вход | Выход | Критичность | Этап |
|---|-------------------|-----------------|------|-------|-------------|------|
| 1 | Декомпозиция запроса | Query Decomposition | User Query (строка) | Query components (entities, concepts, keywords) | Высокая | Stage 1 |
| 2 | Векторный поиск | HNSW Retrieval | Query embedding | Top-K nodes (по cosine similarity) | **КРИТИЧЕСКАЯ** | Stage 2 |
| 3 | Графовый поиск | Personalized PageRank | Seed nodes | Расширенный набор узлов (по релевантности) | Высокая | Stage 3 |
| 4 | Сборка контекста | Context Assembly | Retrieved nodes | Structured context string | **КРИТИЧЕСКАЯ** | Stage 4 |
| 5 | Синтез ответа | Answer Generation (LLM) | Query + Context | Natural language answer | **КРИТИЧЕСКАЯ** | Stage 5 |
| 6 | Постобработка | Post-processing | Raw answer | Formatted answer with citations | Средняя | Stage 6 |

## Детальные характеристики преобразований

### 1. Декомпозиция запроса (Query Decomposition)

#### Семантические характеристики
- **Извлечение сущностей**: Идентификация ключевых сущностей в запросе
- **Идентификация концепций**: Извлечение основных концепций/тем
- **Расширение запроса**: Генерация связанных терминов
- **Нормализация**: Приведение к формату, совместимому с индексом
- **Намерение**: Определение типа запроса (фактический, аналитический, сравнительный)

#### Связь с цепочкой преобразований
- **Вход цепочки**: Первое преобразование в answer pipeline
- **Следующий этап**: Query Components → Retrieval
- **Зависимости**: Нет (начальное преобразование)

#### Роль в генерации ответа
- Преобразует естественный язык в структурированные компоненты поиска
- Улучшает точность retrieval через расширение запроса
- Определяет стратегию поиска

#### Пример
```
Вход: "Какие исследования проводила доктор Эмили Робертс?"

Выход:
{
  "entities": ["DR. EMILY ROBERTS", "ДОКТОР ЭМИЛИ РОБЕРТС"],
  "concepts": ["research", "исследования", "научная работа"],
  "keywords": ["проводила", "studies", "work"],
  "intent": "factual_query",
  "expansion_terms": ["публикации", "проекты", "конференции"]
}
```

#### Подтипы семантических трансформаций
1. **Entity Recognition**: Query text → Named entities
2. **Concept Extraction**: Query → Abstract concepts
3. **Keyword Extraction**: Query → Search keywords
4. **Intent Classification**: Query → Query type
5. **Query Expansion**: Core terms → Expanded term set

---

### 2. Векторный поиск (HNSW Retrieval) ⭐

#### Семантические характеристики
- **Семантическое сходство**: Поиск по смыслу, а не по ключевым словам
- **Многоуровневая навигация**: HNSW обеспечивает быстрый approximate nearest neighbor search
- **Косинусная метрика**: Измерение similarity в векторном пространстве
- **Top-K отбор**: Ранжирование по релевантности

#### Связь с цепочкой преобразований
- **Предыдущий этап**: Query Decomposition → Embedding → HNSW Retrieval
- **Следующий этап**: Retrieved nodes → Graph Expansion (PPR)
- **Параллельный процесс**: Может выполняться для разных типов узлов одновременно

#### Роль в генерации ответа
- **Первичный recall**: Находит начальный набор релевантных узлов
- Обеспечивает семантическую релевантность
- Поддерживает multi-type retrieval (text_units, entities, high_level_elements)

#### Параметры
- **Top-K**: 20-100 (по умолчанию зависит от типа узла)
- **Метрика**: Cosine similarity
- **Типы узлов для поиска**:
  - `text_unit`: Для детальных фактов
  - `entity`: Для сущностей
  - `high_level_element`: Для тематических концепций
  - `semantic_unit`: Для атомарных фактов
  - `attribute`: Для описаний сущностей

#### Пример
```
Вход:
  Query: "Какие исследования проводила доктор Эмили Робертс?"
  Query embedding: [0.234, -0.567, 0.891, ...] (1536 dim)

Выход (Top-K=5):
  1. Entity: DR. EMILY ROBERTS (similarity: 0.92)
  2. Semantic Unit: "Доктор Эмили Робертс опубликовала исследование..." (0.89)
  3. Attribute of DR. EMILY ROBERTS: "Доктор Эмили Робертс - видный..." (0.87)
  4. Text Unit: "В сентябре 2024 года..." (0.85)
  5. High-Level Element: "Исследования в возобновляемой энергии" (0.83)
```

### 3. Графовый поиск (Personalized PageRank) ⭐

#### Семантические характеристики
- **Расширение контекста**: Навигация по связям графа
- **Персонализация**: PageRank с seed nodes из векторного поиска
- **Структурная релевантность**: Учёт топологии графа
- **Multi-hop reasoning**: Обнаружение непрямых связей
- **Вес связей**: Учёт силы отношений (edge weights)

#### Связь с цепочкой преобразований
- **Предыдущий этап**: HNSW Retrieval → Seed Nodes → PPR
- **Входы**: Seed nodes (из векторного поиска) + Knowledge Graph
- **Выход**: Расширенный набор узлов с PPR scores
- **Следующий этап**: Context Assembly

#### Роль в генерации ответа
- **Контекстное обогащение**: Находит связанную информацию
- Обнаруживает неявные связи
- Обеспечивает более полный контекст
- Поддерживает complex reasoning

#### Параметры
- **Alpha**: 0.85 (damping factor)
- **Max iterations**: 100
- **Tolerance**: 1e-6
- **Expansion factor**: 2-3x от seed nodes

#### Пример
```
Вход:
  Seed nodes (из HNSW):
    - DR. EMILY ROBERTS (weight: 0.92)
    - Semantic Unit: "Доктор Эмили Робертс опубликовала..." (0.89)

PPR выполняет random walk и находит:

Выход (дополнительные узлы):
  1. EUROPEAN RESEARCH INSTITUTE (PPR score: 0.78) - через relationship "works at"
  2. SOLAR PANEL EFFICIENCY (0.75) - через relationship "researches"
  3. INTERNATIONAL CONFERENCE ON RENEWABLE ENERGY (0.72) - через semantic_unit
  4. High-Level: "Renewable Energy Research" (0.70) - через community membership
  5. Entity: PARIS (0.68) - через event location
```

#### Типы обнаруживаемых связей
1. **Direct relationships**: Entity → Relationship → Entity
2. **Shared context**: Entities in same semantic_unit
3. **Community co-membership**: Nodes in same cluster
4. **Attribute connections**: Entity → Attribute
5. **Hierarchical links**: Semantic_unit → Text_unit

### 4. Сборка контекста (Context Assembly) ⭐

#### Семантические характеристики
- **Иерархическая организация**: Группировка по типу (themes → entities → relationships → facts)
- **Дедупликация**: Удаление избыточной информации
- **Приоритизация**: Ранжирование по релевантности и важности
- **Управление токен-бюджетом**: Выбор наиболее ценного контента в пределах лимита
- **Структурное форматирование**: Создание секций (THEMES, KEY ENTITIES, RELATIONSHIPS, FACTS)

#### Связь с цепочкой преобразований
- **Предыдущий этап**: PPR → Retrieved nodes → Context Assembly
- **Входы**: Множество разнотипных узлов (entities, semantic_units, attributes, high_level_elements)
- **Выход**: Структурированная контекстная строка
- **Следующий этап**: Answer Synthesis

#### Роль в генерации ответа
- **Структурирование информации**: Организует разрозненные узлы в связный контекст
- Обеспечивает optimal information density
- Поддерживает hierarchical reasoning (от общего к частному)
- Минимизирует информационный шум

#### Стратегия сборки

##### Приоритизация типов узлов
1. **High-Level Elements** (темы) - наивысший приоритет
   - Предоставляют общий контекст
   - Помогают понять "большую картину"

2. **Entities + Attributes** - высокий приоритет
   - Ключевые сущности из запроса
   - Их подробные описания

3. **Relationships** - средний приоритет
   - Связи между сущностями
   - Структурируют знания

4. **Semantic Units** - базовый приоритет
   - Детальные факты
   - Подтверждающая информация

##### Дедупликация
- **Hash-based**: Удаление идентичных узлов (по hash_id)
- **Content-based**: Удаление семантически дублирующегося текста
- **Entity-based**: Объединение упоминаний одной сущности

##### Токен-бюджет
- **Лимит**: 4000-8000 токенов (зависит от модели LLM)
- **Стратегия**: Заполнение по приоритету до достижения лимита
- **Усечение**: Последние, наименее релевантные элементы отбрасываются

#### Пример
```
Вход (retrieved nodes):
  - High-Level Element: "Renewable Energy Research" (PPR: 0.85)
  - Entity: DR. EMILY ROBERTS (PPR: 0.92)
  - Attribute: "Доктор Эмили Робертс - видный исследователь..." (PPR: 0.87)
  - Entity: EUROPEAN RESEARCH INSTITUTE (PPR: 0.78)
  - Relationship: "DR. EMILY ROBERTS, works at, EUROPEAN RESEARCH INSTITUTE"
  - Semantic Unit: "В сентябре 2024 доктор Эмили Робертс посетила..."
  - Semantic Unit: "Исследование показало повышение эффективности на 15%"

Выход (assembled context):
```
=== ТЕМЫ ===

сотрудничестве через научные конференции.

#### Подтипы семантических трансформаций
1. **Hierarchical Grouping**: Flat nodes → Structured sections
2. **Deduplication**: Multiple mentions → Single representation
3. **Prioritization**: Retrieved nodes → Ranked nodes
4. **Summarization**: Verbose content → Concise content (if needed)
5. **Formatting**: Structured data → Readable text

### 5. Синтез ответа (Answer Synthesis) ⭐

#### Семантические характеристики
- **Информационный синтез**: Объединение множественных фактов в связный ответ
- **Стилевая адаптация**: Профессиональный, разговорный тон
- **Интеграция цитирований**: Корректная ссылка на источники
- **Проверка полноты**: Убеждение, что все аспекты запроса раскрыты
- **Фактическая обоснованность**: Ответ в рамках предоставленного контекста
- **Нарративная конструкция**: Создание плавного, читаемого ответа

#### Связь с цепочкой преобразований
- **Предыдущий этап**: Context Assembly → Answer Synthesis
- **Входы**: User Query + Assembled Context
- **Выход**: Natural language answer
- **Следующий этап**: Post-processing (опционально)

#### Роль в генерации ответа
- **Финальная трансформация**: Преобразует структурированный контекст в естественный ответ
- Обеспечивает читаемость и связность
- Адаптирует стиль под пользователя
- Гарантирует фактическую точность

#### Параметры
- **Temperature**: 0.7-1.0 (для естественности ответа)
- **Max tokens**: 500-2000
- **Top-p**: 0.9
- **Frequency penalty**: 0.3

#### Стратегия синтеза

##### Структура ответа
1. **Прямой ответ**: Непосредственный ответ на вопрос
2. **Поддерживающие детали**: Контекст и дополнительная информация
3. **Связывание информации**: Объединение фактов из разных источников
4. **Заключение**: Обобщение (если уместно)

##### Приёмы синтеза
- **Fact merging**: Объединение связанных фактов
- **Temporal ordering**: Упорядочивание событий по времени
- **Causal linking**: Установление причинно-следственных связей
- **Contextual embedding**: Встраивание деталей в нарратив

#### Пример
```
Вход:
  Query: "Какие исследования проводила доктор Эмили Робертс?"

  Context: [структурированный контекст из предыдущего примера]

Выход (Answer):

"Доктор Эмили Робертс проводит исследования в области возобновляемой энергии,
специализируясь на технологиях солнечных панелей. Её работа направлена на повышение
эффективности фотоэлектрических систем, и она опубликовала результаты, демонстрирующие
15%-ное увеличение эффективности солнечных панелей.

Как ведущий учёный Европейского исследовательского института, доктор Робертс активно
участвует в международном научном сообществе. В сентябре 2024 года она представила
своё революционное исследование на Международной конференции по возобновляемой энергии
в Париже, подчёркивая его значимость для развития устойчивой энергетики.

Её исследования имеют практическое применение: доктор Робертс установила партнёрства
с европейскими компаниями для внедрения передовых технологий в области возобновляемой
энергии, способствуя переходу к более экологичным энергетическим решениям."
```

#### Подтипы семантических трансформаций
1. **Information Fusion**: Multiple facts → Coherent narrative
2. **Style Transformation**: Structured data → Conversational text
3. **Temporal Organization**: Unordered facts → Timeline
4. **Causal Reasoning**: Correlations → Cause-effect relationships
5. **Abstractive Summarization**: Detailed context → Concise answer

### 6. Постобработка (Post-processing)

#### Семантические характеристики
- **Форматирование**: Добавление Markdown форматирования
- **Цитирование**: Вставка ссылок на источники
- **Валидация**: Проверка качества ответа
- **Фильтрация**: Удаление нерелевантной информации

#### Связь с цепочкой преобразований
- **Предыдущий этап**: Answer Synthesis → Post-processing
- **Конец цепочки**: Финальный ответ пользователю

#### Роль в генерации ответа
- Улучшение читаемости
- Добавление метаинформации
- Обеспечение корректности формата

#### Пример
```
Вход: Raw answer (текст выше)

Выход: Formatted answer with citations

"Доктор Эмили Робертс проводит исследования в области возобновляемой энергии,
специализируясь на технологиях солнечных панелей[1]. Её работа направлена на повышение
эффективности фотоэлектрических систем, и она опубликовала результаты, демонстрирующие
**15%-ное увеличение эффективности** солнечных панелей[2].

Как ведущий учёный *Европейского исследовательского института*, доктор Робертс активно
участвует в международном научном сообществе[3]...

---
Источники:
[1] Attribute: DR. EMILY ROBERTS
[2] Semantic Unit: "Исследование показало повышение эффективности на 15%"
[3] Relationship: DR. EMILY ROBERTS, works at, EUROPEAN RESEARCH INSTITUTE
```

## Цепочка преобразований при генерации ответа

```
❓ User Query
     ↓
[1] Query Decomposition
     ↓
{entities, concepts, keywords, intent}
     ↓
     ├─→ Embedding Generation
     │        ↓
     └─→ [2] HNSW Retrieval ⭐
              ↓
         Top-K Nodes (seed nodes)
              ↓
         [3] Personalized PageRank ⭐
              ↓
         Expanded Node Set
              ↓
         [4] Context Assembly ⭐
              ↓
         📋 Structured Context
              ├─ THEMES (High-Level Elements)
              ├─ KEY ENTITIES (Entities + Attributes)
              ├─ RELATIONSHIPS (Entity connections)
              └─ FACTS (Semantic Units)
              ↓
         [5] Answer Synthesis ⭐ (LLM Generation)
              ↓
         📝 Natural Language Answer
              ↓
         [6] Post-processing
              ↓
         ✅ Final Answer to User
```

## Ключевые метрики преобразований

| Преобразование | Latency | Критичность | Факторы влияния | Оптимизация |
|---------------|---------|-------------|-----------------|-------------|
| Query Decomposition | ~100ms | Высокая | Длина запроса, сложность | Кэширование типовых запросов |
| HNSW Retrieval | ~50-200ms | **КРИТИЧЕСКАЯ** | Top-K, размер индекса | HNSW параметры (M, ef) |
| Personalized PageRank | ~200-500ms | Высокая | Размер графа, expansion factor | Alpha, max_iterations |
| Context Assembly | ~100-300ms | **КРИТИЧЕСКАЯ** | Количество узлов, токен-бюджет | Эффективная дедупликация |
| Answer Synthesis | ~1-3s | **КРИТИЧЕСКАЯ** | Размер контекста, max_tokens | Prompt optimization, streaming |
| Post-processing | ~50ms | Средняя | Сложность форматирования | - |

**Общая latency**: ~2-5 секунд (для типичного запроса)

## Стратегии оптимизации

### 1. Hybrid Retrieval
- **Векторный + Графовый**: Комбинирование HNSW и PPR
- **Multi-type retrieval**: Параллельный поиск по разным типам узлов
- **Re-ranking**: Дополнительное ранжирование после PPR

### 2. Context Management
- **Adaptive token budget**: Динамическая настройка лимита токенов
- **Intelligent pruning**: Удаление наименее релевантных элементов
- **Hierarchical context**: Приоритет высокоуровневых элементов

### 3. Answer Quality
- **Multi-turn refinement**: Итеративное улучшение ответа
- **Citation validation**: Проверка корректности цитирований
- **Completeness check**: Проверка полноты ответа

## Сравнение с индексацией

| Аспект | Индексация | Генерация ответа |
|--------|-----------|------------------|
| **Направление** | Document → Structured knowledge | Query → Natural answer |
| **Основная цель** | Структурирование и обогащение | Поиск и синтез |
| **Детерминизм** | Высокий (Temperature 0.0) | Средний (Temperature 0.7-1.0) |
| **Latency** | Высокая (минуты) | Низкая (секунды) |
| **Batch processing** | Да | Нет (real-time) |
| **LLM роль** | Extraction, Summarization | Synthesis, Generation |
| **Критичные этапы** | Decomposition, Attribute, Community | Retrieval, Context Assembly, Synthesis |

## Типы семантических трансформаций

### В генерации ответа (vs индексации)

| Тип трансформации | Индексация | Генерация ответа |
|-------------------|-----------|------------------|
| **Extraction** | ✅ Извлечение фактов из текста | ✅ Извлечение компонентов запроса |

- **Индексация** фокусируется на **структурировании и обогащении** знаний
- **Генерация ответа** фокусируется на **навигации и синтезе** из структурированных знаний
